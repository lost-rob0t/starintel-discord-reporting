# Auto-Research pins StarIntel's strict JSON boundary

## Changes

- Current-source research confirms StarIntel's shared HTTP JSON boundary still has a strictness defect: trailing-comma JSON can pass the existing YASON validation path before JSOWN conversion.
- The landed `STAR-SERVER-060` design selects Jzon as the one parser allowed to read untrusted request bytes, with comments, trailing commas, and multiple top-level values disabled, duplicate keys rejected, and explicit depth/string limits.
- Malformed input must stay side-effect-free and preserve the existing client-safe HTTP error contract; accepted input is converted in memory for current JSOWN-facing services instead of reparsing attacker-controlled text.
- This is design-ready for operator review only. Architecture approval and implementation authorization remain `PENDING`; no StarIntel Server runtime behavior changed with these commits.
