# Auto-Research adds the target-lease crash/race proof layer

## Changes

- The canonical target-lease stack now includes issue #33 recovery and race proofs for expiry, crashes, ambiguous backend outcomes, revocation, restart/failover, and delayed stale writers.
- `STAR-SERVER-045` defines one LR-* scenario matrix across deterministic schedules, backend-neutral lease contracts, real Valkey evidence, and the production fenced-effect boundary. The mandatory end-state proof is A/fence N stalls, B reacquires N+1 and commits, then A resumes and its stale effect is rejected without changing authoritative state.
- Recovery explicitly does not create authority: persisted `running` state or actor/process liveness cannot substitute for a current lease, unknown mutation outcomes must resolve the original request identity first, and an uncertain restored fencing floor fails closed.
- This is research/design-ready only. Operator architecture review and implementation authorization remain `PENDING`.
