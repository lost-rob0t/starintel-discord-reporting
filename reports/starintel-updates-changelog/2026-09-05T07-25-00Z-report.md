## 🧠 Only losers use `if / else`

Okay, that's bait. But there is a real architectural point underneath it.

## Changes

A lot of agent systems eventually turn into a pile of booleans and nested conditionals trying to answer one question: **is this actually done?**

Our OpenCode Prolog verification skill takes a different route. The agent writes down requirements, machine observations, repository state, research requirements, and invariants as facts, then asks Prolog whether the evidence is sufficient.

A real schema from the skill looks like this:

```prolog
requirement_satisfied(Requirement) :-
    requirement(Requirement, _),
    supports(Observation, Requirement),
    observation(Observation, _, exit(0), _, Head, Digest),
    repo_state(Head, Digest).
```

That means a requirement is not satisfied because the model says "looks good." It needs a successful machine observation that supports the requirement **and belongs to the current repository state**.

Research can be part of the proof too:

```prolog
current_research_evidence :-
    research_required(false).
current_research_evidence :-
    research_required(true),
    repo_state(Head, Digest),
    brave_search(_, _, _, Head, Digest).
```

If the task says research is required, completion requires recorded research evidence for the current workspace state. The skill now has a fixed Brave-search path that records the search and its result together instead of trusting a model to remember that research happened.

The same pattern lets agents express security requirements, deployment requirements, expected failures, and invariants as executable logic. An exit code of `1` can even be the correct evidence when the requirement is "this service must fail closed without credentials."

So the flow is increasingly:

```text
TASK
  -> REQUIREMENTS
  -> RESEARCH / INVARIANTS
  -> MACHINE OBSERVATIONS
  -> SYMBOLIC EVIDENCE
  -> PROLOG DERIVATION
  -> COMPLETE / NOT COMPLETE
```

> **Only losers use `if / else`. Winners write down what must be true and ask Prolog whether they can prove it.**

More seriously: the model proposes, the machine observes, and Prolog keeps the receipts. That lets us push agent autonomy and rate of change without making the agent's own confidence the final authority.
