# Zara: local Prolog Studio, on-device AI, and phone-driven watch setup

September 17, 2026. This update covers new landed work since the previous Zara changelog, not the open-PR wish list. Android now has a local expert-authoring workspace, an embedded model service, executable automation plans, and a watch installer. Desktop chat and the voice path also received concrete fixes.

**Build snapshot checked at 05:57 UTC:** `android-latest` points to `ec9756e56537ee85f165291499ceb6312ee84451`. The newer local-first repair, `8a11e9c583a5539c187633bcf87901111e2cc827`, is merged on `master` but was not in that downloadable snapshot. The distinction matters for anyone testing the local-mode bug.

## Changes

### Write and inspect local experts on Android

Prolog Studio is more than a text box. The merged workspace supports source editing, deterministic syntax and semantic highlighting, diagnostics, workspace-aware completion, bounded queries, undo/redo, literal search, source rename, and private-workspace import/export. Fact/rule graphs, an expert generator, examples, and tutorials sit beside the editor so an author can move from a rule to its query result without leaving the app.

The embedded Trealla runtime has one serialized local-server owner. Editing, consulting, and querying go through that owner rather than independent screens racing over shared interpreter state. Typed schema checks validate predicate arity and arguments. Bundled/runtime/plugin sources remain read-only; the editable workspace belongs to the user.

The practical change: a phone can author and inspect local symbolic behavior rather than serving only as a remote chat terminal. This is the landed Studio implementation, not a claim that every requested desktop IDE feature already has Android parity.

Authoring tools: <https://github.com/lost-rob0t/zara/commit/82496e16b9081ff84c59ce52bfab02af0c4e0f5f>

### Local language models and offline speech have their own service

The new Android local-AI service owns model load, generation, cancellation, and unload on a serialized actor lane. Local text takes the Prolog path first. When deterministic symbolics do not match, the selected embedded model can provide conversational fallback. A local inference failure does not silently send the request to a network provider.

The model catalog can retain multiple verified installations and select by model ID and version. Model descriptors carry explicit format, quantization, context, backend, and SHA-256 metadata. Imported files are checked again in app-private storage before use.

Actual backend support is narrower than the shared vocabulary: the built-in `embedded` provider executes compatible LiteRT-LM containers. GGUF, ONNX, and TFLite names in the common contract are extension points, not proof that those backends already run. Model weights still need to be installed; downloading the APK is not the same as downloading a language model.

Speech is independently selectable. The initial offline TTS provider uses an installed Android voice that does not require a network connection. Barge-in stops that speech as well as remote PCM playback. This does not claim a bundled neural voice model or measured acceleration on every handset.

Landed implementation: <https://github.com/lost-rob0t/zara/commit/ec9756e56537ee85f165291499ceb6312ee84451>

### Prolog automation can reach Android actions

The merged local automation API can launch reviewed app aliases, open URIs, search inside supported apps, click typed accessibility selectors, set text, scroll, and invoke supported global navigation actions. The included examples search YouTube and YouTube ReVanced for psytrance.

Android owns special-access grants. Zara exposes the relevant Assistant, Accessibility, Usage, Write Settings, and Overlay request surfaces; a plan that needs missing access returns a permission requirement instead of pretending the action succeeded. Local automation does not silently widen the remote device protocol into arbitrary Android execution.

Public HTTPS Git repositories can also supply configuration templates, including supported Org `:tangle` content. Imports report the revision, validate bounded content and paths, and apply through the private workspace transaction rather than replacing the live configuration halfway through a failed import.

Automation and templates: <https://github.com/lost-rob0t/zara/commit/e8e8382ddea3a48b1b67de9146e5e8ae6d17645f>

### The local-mode repair is merged, but check the APK revision

A stale unversioned Remote preference could leave chat looking local while submission still waited for remote enrollment. The repair makes fresh installs Local, migrates that legacy preference once, and preserves a later explicit Remote choice. It also accepts Trealla's canonical character-list rendering of quoted automation text, fixing a mismatch that could reject the example search text. Automation controls received theme and sizing fixes in the same change.

This repair is newer than the APK snapshot named above. Users affected by local submission or quoted-text errors should check the rolling manifest for this commit before treating a reinstall as a verified fix.

Merged repair: <https://github.com/lost-rob0t/zara/commit/8a11e9c583a5539c187633bcf87901111e2cc827>

### Set up Zara Wear from the phone

Zara Watch Setup discovers Bluetooth-paired watches, reachable Wear Data Layer nodes, and wireless-debugging endpoints. The phone can pair using the watch's code, connect, download the Wear APK, verify its SHA-256, and install it through the in-app ADB path. Phone/watch identity and signing hooks were aligned for Data Layer discovery, with migration handling for the older Wear package.

The transport distinction is explicit: Bluetooth assists paired-watch discovery and normal Data Layer communication. The one-time Zara APK sideload uses Wireless ADB over Wi-Fi. This is not a claim that raw Bluetooth ADB installation exists on current Wear OS, or that a physical Galaxy Watch installation was verified during this changelog pass.

Watch setup: <https://github.com/lost-rob0t/zara/commit/5910759379ff623dad83bbd5703629445e3a063a>

### Desktop and voice fixes that change daily use

Desktop Copilot now uses message bubbles, clears stale content when creating a chat, and renders generic plugin-tool activity in the conversation. Separately, the voice path gained Pulse-compatible playback, a capture-stall watchdog, and configurable speech-decoder beam size. The watchdog gives a stalled microphone path a bounded failure instead of leaving it wedged indefinitely.

Desktop: <https://github.com/lost-rob0t/zara/commit/812d202c0b061a05a081ae8c94f5b02a349954ad>
Voice: <https://github.com/lost-rob0t/zara/commit/8bb909798047eb3558623bd139e610ede87c44f6>
