# STAR SERVER STOPPED REUSING DEAD COUCHDB SESSIONS

## Changes

A pooled CouchDB client could outlive its authenticated session and get reused later like nothing happened. PR #107 landed the fix: pooled clients are now checked against `/_session` before reuse, stale sessions are discarded, and replacements are authenticated before going back into service.

The HTTP-facing pool and the auth-store pool now share the same session-validity check, so this is one renewal policy instead of two places quietly drifting apart.

>session expires
>pool still has object
>object is technically alive
>auth is not
>computer discovers these are different concepts
