# PROLOG-RLM NOW OWNS SKILL ACTIVATION IN PROLOG

## Changes

- `SKILL.md` packages are now discovered and normalized behind a confined Prolog runtime boundary instead of being model-selected blobs.

- The prompt compiler decides which skills enter provider context, keeps resources lazy until an explicit confined read, and does not let skill text grant tools, authority, or execution permission.

- Host policy can pin mandatory skills, while the runtime keeps bounded prompt-cost accounting and deterministic activation explanations.

- The landed change also adds four default RLM operating skills and optional pinned third-party skill material without turning those instructions into executable authority.
