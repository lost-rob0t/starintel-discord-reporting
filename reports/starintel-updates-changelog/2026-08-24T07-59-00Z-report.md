# STAR URIS JUST GOT A REAL STANDARD

## Changes

- STAR-SERVER-041 is now approved at the architecture level. The new canonical `star://` model uses RFC 3986 hierarchical authority/path semantics instead of carrying the old actor-only `domain:address:actor-name` shape forward.
- STAR identity is transport-neutral. Authorities own resource namespaces, while StarRouter resolves authority/resource prefixes without baking the current network endpoint into the identifier.
- The approved extension also keeps legacy StarLang URIs as migration input, gives the StarIntel gserver an authority-owned namespace, and leaves durable FediWatch target/output/checkpoint flow on RabbitMQ.
- This is design approval, not a fake "shipped" claim. Security review and implementation gates are still pending.
