# Zara Android now fences remote work when strict Local takes over

## Changes

- Zara landed a backend-neutral `ZARA-RUNTIME/1` registry in Python and Android. Runtime discovery and selection share one bounded contract, stale publications are generation-fenced, duplicate runtime IDs fail atomically, and absent runtimes cannot be selected.
- Strict Local can now sever an active or reconnecting remote text session without losing the configured server profile. It bumps the runtime generation, clears the remote session, stops queued reconnects, and rejects late remote connect or turn completions instead of letting stale network work become current again.
- The Android Trealla JNI bridge also fixed its `pl_query` return handling, which had inverted Trealla's error semantics and could reject valid local Prolog queries as native failures.
- Portable local conversation persistence landed on one canonical schema shared with Desktop. Crash recovery converts unfinished local turns to cancelled, principal migration stays bounded, and late writes cannot overwrite terminal message state.
