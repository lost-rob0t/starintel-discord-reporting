# Auto-Research separates Actor Studio from runtime topology

## Changes

Research/design for Quasar found that Actor Studio should not become a dump of every live Common Lisp, Sento, or cl-gserver process. The operator needs semantic capabilities they can intentionally run, filtered by the target or document types those capabilities actually accept.

The proposed catalog gives each operator-visible actor a versioned descriptor: what it accepts, what it produces, whether it can preview/run, and which runtime backend resolves it. Runtime topology stays separate as an observation/admin plane for liveness and supervision.

Concrete example: a `Normalize person` capability can advertise that it accepts `person` documents and produces updated `person` documents, while cl-gserver remains the backend detail that actually executes it. Actor Studio answers “what can I run here?” Runtime topology answers “what is running right now?”

This is research/design, not shipped Quasar behavior.
