# Auto-Research finds StarIntel's URL extractor is wired to nowhere

Research on `starintel-server` #44 found the matcher subsystem is loaded and `start-url-extractor` registers a global pattern, but current server source has no canonical-document consumer that actually walks that registry. The extractor can exist while the registered pattern does no ingest work.

The proposed replacement is narrower and less cursed: immutable StarLang-first `DocumentTransform` bindings compile into the runtime plan, run with hard input/output/deadline bounds, and send generated URL + relation documents back through canonical ingest. No arbitrary Lisp callback bag. No raw actor subscription surviving restarts. No treating a Rabbit publish as proof the document was accepted.

For the first HTTP(S) transform, candidate discovery stays bounded and deliberately dumb, then the existing URI parser handles validation/normalization. Extraction does not fetch the URL and does not claim reachability, ownership, or corroboration.

This is research/design, not shipped server behavior. Implementation is still gated.
