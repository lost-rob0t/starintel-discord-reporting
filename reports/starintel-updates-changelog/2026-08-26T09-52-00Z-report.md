## AUTO-DIG RUNS CAN SURVIVE A QUASAR RESTART NOW

## Changes

Quasar's local Auto-Dig control plane now has a filesystem-backed run store instead of making run lifecycle depend on one live process.

Run state goes through the same control path whether the backend is in-memory or persistent. Restart conflicts and lifecycle transitions are covered, and Quasar can load the backend from its initfile at startup.

So the semantic split stays clean: actors dispatch the work, workers hold temporary leases, and the run itself can outlive either one.
