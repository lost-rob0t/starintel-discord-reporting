# Hackmode rejects visual evidence written into the wrong run

## Changes

Visual evidence persistence now checks that a record belongs to the expected operation and run before the canonical write happens.

Cross-operation and cross-run writes fail at the database boundary, while replay-safe records keep stable identity and deterministic retrieval order. That closes a nasty evidence-mixing failure mode without changing the existing replay contract.
