# Auto-Research makes StarIntel manifests compile before runtime

## Changes

Auto-Research landed the actor/dataset manifest runtime-plan design. StarLang stays authoritative for actor and domain semantics; StarIntel deployment manifests bind those immutable semantic artifacts to runtime components instead of redefining capabilities, message types, or failure policy.

Actor deployment bindings, dataset manifests, locked StarLang semantic manifests, and runtime policy now converge on one pure deterministic `RuntimePlan` before long-lived side effects. Threads, actor systems, Rabbit/Couch connections, timers, listeners, and tool processes are not supposed to start until semantic linking plus capacity and lifecycle validation pass.

The design also makes narrowing explicit: deployment can reduce allowed capacity or disable optional capability, but it cannot widen the semantic contract emitted by StarLang.

Status is **design-ready for operator review only**. Research, architecture/design, implementation, and publication approval rows remain pending.
