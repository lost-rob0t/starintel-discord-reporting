# Auto-Research gives StarIntel component refs a generation

## Changes

Auto-Research landed the runtime component-handle design as a projection over the existing `star.runtime` lifecycle registry, not a second component manager.

Public component refs become opaque `{runtimeId, componentId, generation}` handles. Restart or replacement advances the generation, and stale handles must fail instead of silently resolving to the new incarnation. Raw actor refs, broker/database resources, HTTP handles, threads, and other runtime internals stay private.

Capability lookup remains discovery, not authorization. Readiness is also explicit now: required component health plus dependency state drives readiness, while optional failures can surface as degraded instead of pretending a non-NIL object means healthy.

This is **design-ready for operator review only**. Architecture/security approval and implementation authorization are still pending.
