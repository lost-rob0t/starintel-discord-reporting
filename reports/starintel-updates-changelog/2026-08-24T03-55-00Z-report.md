# THE MCP PLAN GOT LESS DERANGED

## Changes

- The landed research direction now puts a **full StarIntel MCP** in front of the narrower Meta MCP instead of stuffing everything into one giant agent endpoint.
- The full MCP is supposed to reuse the existing StarIntel gserver client, which means one data/API path instead of inventing another transport stack for the same backend.
- The Meta MCP boundary is now deliberately thin: search/fetch-oriented access only, with crawl/research kept out of that service and pushed to separate agent work later.
