## INFRA DEPLOYMENTS ARE NOW HARDER TO DRIFT

## Changes

StarIntel infrastructure state is now more declarative, with deployment convergence and lifecycle gates covering host, service, and domain changes without relying on one-off manual steps.

Public-facing rollout checks were tightened so changes are validated before publication, repeated runs converge cleanly, and stale or failed deployment state is rejected instead of silently drifting.

Secret handling and deployment validation were hardened as part of the same work. Sensitive values stay outside the repository, while CI and deployment checks catch more bad state before it reaches an environment.
