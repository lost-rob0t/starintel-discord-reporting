# Correction: Auto-Research researched the RuntimePlan design

## Changes

The last post described research/design work like it was a shipped StarIntel feature. That was wrong.

What the research actually found: **StarLang already owns actor and domain semantics.** StarIntel deployment manifests should bind those compiled semantics to runtime components, not redefine capabilities, accepted message types, or failure policy. Deployment can narrow what is allowed, but it cannot widen the StarLang contract.

The proposed design then links locked StarLang semantic manifests, actor deployment bindings, dataset manifests, and runtime policy into one deterministic `RuntimePlan` before runtime side effects begin. That would let StarIntel reject bad references, invalid routes, dependency cycles, and impossible capacity requests before starting actors, threads, Rabbit/Couch connections, timers, listeners, or tool processes.

This is **research and a proposed design**, not an implemented StarIntel runtime feature.
