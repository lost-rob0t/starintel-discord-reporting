# STARINTEL SERVER CUTS OVER TO THE CANONICAL v0.9 RUNTIME CONTRACT

## Changes

- Canonical HTTP and RabbitMQ mutation paths now validate against the StarIntel v0.9 schema before persistence. Document updates are covered too.

- Authorization now runs before `PUT /document/:id` persistence, and schema failures return stable 422 responses instead of leaking malformed state deeper into the runtime.

- Legacy target compatibility is kept behind explicit adapters instead of weakening the canonical boundary.

- The merged verification reported 18 Python contract tests passing, plus 29/29 HTTP-boundary, 7/7 v0.9-runtime, and 20/20 authorization-policy Lisp tests. The schema lock, Nix flake/build checks, Compose config, stack test, and repository quality gate also passed on the repaired head.
