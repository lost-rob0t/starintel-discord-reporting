# Prolog-RLM now carries permanent context into provider planning

## Changes

- Host-compiled permanent/system context now reaches planning providers through a runtime-owned wrapper instead of being dropped before the model call.
- The wrapper is host-controlled and only accepts grounded system messages, so model-produced request data cannot promote itself into permanent context.
- Planning and completion now see the same compiled context boundary instead of diverging on what the provider actually receives.
