# QUASAR FINALLY HAS ONE UI SHELL INSTEAD OF THREE NEAR-COPIES

## Changes

Quasar now uses one shared application shell across the Common Lisp control plane, standalone browser UI, and Auto-Dig embedding. Navigation, status, graph chrome, responsive behavior, and design tokens now live behind one UI-core boundary with deployment-specific adapters.

Datasets are a first-class route, runtime/service health is exposed through one status center, and mobile and desktop use the same navigation model instead of separate route logic.

The same shell was mirrored into standalone Quasar and Auto-Dig, so those surfaces can diverge by capability without forking the whole interface again.

>one shell
>three runtime adapters
>graph stops rewriting the entire app
>civilization advances
