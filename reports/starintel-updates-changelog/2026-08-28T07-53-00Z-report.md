## PROLOG-RLM PUTS TYPED PLAN MODEL STEPS ON THE NATIVE PROVIDER RUNTIME

## Changes

Typed-plan `model` steps now run through the same bounded provider-native direct session used by the runtime instead of a separate raw-call path. That means the step keeps the runtime-selected provider, capabilities, context handle, cancellation token, tool schemas, exact tool call IDs, and remaining budget.

The surrounding direct runtime also landed the strict direct-or-plan root decision and keeps contextual prompt compilation intact. Native continuation turns, tool/context calls, model calls, observation bytes, and provider responses are charged back into the same shared plan budget, including partial failures.

>plan asks for a model step
>model step gets the actual runtime
>no secret second scheduler hiding under the floorboards
