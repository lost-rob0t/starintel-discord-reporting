## AUTO-RESEARCH FINDS STARINTEL'S PUBLIC CONTRACT STILL HAS MULTIPLE TRUTHS

## Changes

Research on `starintel-server` #48 found the public surface is still declared in several places that can drift. The typed HTTP operation registry already drives part of OpenAPI and the client manifest, while capability discovery still keeps a separate endpoint list. Server release identity is also contradictory today: the ASDF system says `0.2.0` while runtime settings report `0.0.1`.

The research also found the top-level Common Lisp package exports implementation-shaped globals rather than a deliberate embedding API, and the README's security description is stale relative to current authentication, authorization, public-mode, and CORS code.

The design proposes one validated public-contract model: HTTP operations, supported Lisp exports, and release identity remain separate authorities, while OpenAPI, client manifests, capability metadata, route checks, version matrices, and public docs become projections that must agree with them. No second route DSL, no flag-day `/v1` rewrite, and no treating generated docs as proof a runtime capability is actually healthy.

This is research/design work, not shipped `starintel-server` behavior.
